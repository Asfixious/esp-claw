## 职责

`claw_event_router` 接收结构化的 Event `claw_event_t`，再按 `router_rules.json`（或运行时增删改的规则）做匹配，执行一串动作（如调用 Capability、运行 Lua、发送消息、继续抛事件等）。

`claw_event_router` 的运作流程与 `router_rules.json` 的详细语法定义见 [数据流与自动化](@lang/reference-project/dataflow-and-automation)。

## 事件来源

能力实现（尤其是 IM gateway、MCP 等）在合适时机调用 `claw_event_router_publish_message` 或 `claw_event_router_publish_trigger` 发布事件。`cap_agent` 独占消费每个已打开 `claw_agent.h` Session 的 stream，并将完整 Agent 响应发布为 `out_message` 事件；
工具调用会转换为 `agent_stage` 事件（见 [数据流与自动化](@lang/reference-project/dataflow-and-automation#agent_stage-事件与执行过程通知)）。

路由任务异步处理队列中的事件，避免在回调栈里承担 CPU 负担较重的任务。

## 与 cap_agent 的衔接

Agent 输入使用普通 `call_cap` 动作，指定 `cap: "agent"` 和 RPC envelope `{"method":"session.input","args":{"text":"..."}}`。Event Router 通过 `claw_cap_call_context_t` 透传事件的 Session、request、route 与 correlation 字段。`cap_agent` 立即接收输入，完成后再发布 `source_cap=agent,event_type=out_message`。

`claw_event_router_config_t` 中常见字段含义：

- `default_route_messages_to_agent`：是否在没有规则命中时，把某类消息默认送给 Agent。
- `default_route_agent_output_to_channel`：未匹配规则的 Agent `out_message` 是否按事件路由使用出站绑定。
- `outbound_resolver`：可选回调，在出站绑定表之前解析 `target_channel` 到 cap 名。

`edge_agent` 同时启用两个默认路由；显式匹配的规则仍优先于 fallback。

<Aside type="caution" title="Agent 输入仍要求有效的 LLM API binding">
  即使初始 API 字段为空，`edge_agent` 也会初始化并启动 AgentSystem。
  在绑定有效 API 前，Session 输入仍不可用；Event Router、自动化规则、本地 Capability 和 Console REPL 可继续使用。
</Aside>

## 队列取消与清理

`claw_event_router` 提供了两个“待处理事件队列”管理接口：

- `claw_event_router_cancel_event(event_id)`：取消（跳过）指定 `event_id` 的待处理事件。
- `claw_event_router_purge_queue(event_type_filter, source_cap_filter, &out_cancelled)`：批量取消待处理事件，可按 `event_type`、`source_cap` 过滤，并返回本次标记数量。

<Aside type="note">

  - 这两个接口作用于“队列里尚未被处理”的事件，不会中断已经在执行中的动作。
  - 若指定 `event_id` 不存在于待处理队列，`claw_event_router_cancel_event` 将返回 `ESP_ERR_NOT_FOUND`。
  - 适用于做“快速止损”：例如清空某类触发洪峰、撤销尚未执行的批量自动化事件。

</Aside>

## 出站通道绑定

`claw_event_router_register_outbound_binding(channel, cap_name)` 把逻辑 channel 名映射到真实 Capability 名。

提供用户交互的「组件」在 ESP-Claw 中也是一种 Capability。它将用户消息包装为 Event 时会添加 `channel` 字段，标示消息来源，并充当由该 Event 触发的一系列 Event 的默认目标 `channel`。
当 Event Router 接收到最终发送消息的 Event 时，会根据目标 `channel` 字段找到对应的 Capability 并调用其 `send_message` 动作。若配置了 `outbound_resolver`，则先调用自定义解析器，未命中再查表。

`edge_agent` 中，QQ、飞书、Telegram、微信、Web（本地 IM）分别绑定了其发送消息的函数与 `channel` 名称。

## 会话策略

`claw_event_session_policy_t` 影响 `claw_event_build_session_id` 如何为事件生成 session id，从而决定与 `claw_memory` / `claw_skill` 会话状态的对应关系。

| 策略 | 说明 |
|------|------|
| `CHAT` | 按 `source_channel:chat_id` 生成，同一聊天窗口共享会话 |
| `TRIGGER` | 按 `trigger:source_cap:event_key` 生成，每类触发源独立会话 |
| `GLOBAL` | 按 `global:source_cap` 生成，同一来源 cap 共享全局会话 |
| `EPHEMERAL` | 按 `ephemeral:event_id` 生成，每个事件独立的一次性会话 |
| `NOSAVE` | 生成空 session id（长度为 0），不保存会话历史 |

<Aside type="tip">

  调用自动化或 IM 时，若发现「记忆杂糅」或「Skill 激活态异常」，可检查规则中 `session_policy` 与事件字段是否一致。

</Aside>
