## 职责

`claw-agent` 是组装 AgentSystem 的公开 Rust 边界，拥有 Sessions、模型绑定、工具、持久化与生命周期驱动。`claw-cabi` 通过 `claw_agent.h` 将该 runtime 导出给 ESP-IDF。

C 应用不会复制 Agent loop，而是通过仅供系统调用的 `cap_agent` RPC adapter 访问它，并以 Event Router 事件接收异步结果。

```d2
app: "app_claw\n生命周期 + API 配置"
rpc: "cap_agent\nmethod + args"
runtime: "claw-agent\nAgentSystem + Sessions"
router: "Event Router\nout_message"

app -> runtime: "claw_agent_init/start/link_api"
rpc -> runtime: "claw_agent_session_*"
runtime -> rpc: "Session event stream"
rpc -> router: "claw_event_router_publish"
```

## 生命周期

| API | 效果 |
| --- | --- |
| `claw_agent_init` | 构造一个 stopped AgentSystem、恢复持久化，并可选绑定初始 root API |
| `claw_agent_link_api` | 为 root Agent、subagent、memory 或 compaction 绑定或替换 API |
| `claw_agent_start` | 激活工具并启用 Session 操作，不重建 AgentSystem |
| `claw_agent_stop` | 停用工具，但保留 bindings、Sessions、已打开 streams 与 runtime 状态 |
| `claw_agent_deinit` | 必要时先停止，再销毁保留的 AgentSystem |

四个初始 API 字段可以全部为空，以创建 unbound runtime，之后通过 `claw_agent_link_api` 配置；只配置一部分会被拒绝。

API 替换在下一轮 turn boundary 生效，不会干扰正在执行的 turn。

## Sessions

Session 使用非零 numeric `uint32_t` ID；创建时必须明确选择 `PERSISTENT` 或 `EPHEMERAL`。

主要操作包括：

- `claw_agent_session_create` / `list`
- `claw_agent_session_open`
- `claw_agent_session_submit`
- `claw_agent_session_respond`
- `claw_agent_session_interrupt` / `cancel`
- `claw_agent_session_receive`
- `claw_agent_session_close` / `delete`

`submit` 将输入追加到 Session FIFO，即使另一 turn 正在执行也可以排队。`respond` 不同：它恢复当前 turn，并要求使用 `INPUT_REQUESTED` 给出的 `request_id`。

打开 Session 会创建一个 event stream。在生产 IM/RPC 链路中，`cap_agent` 是唯一 stream consumer，并为每个已打开 Session 运行一个 event pump。诊断 CLI 只拥有自己创建的 ephemeral streams。

## Events 与所有权

`claw_agent_session_receive` 返回 tagged `claw_agent_event_t`；只能读取 `kind` 选择的 union member。

stream 包含 turn 边界、输入请求、iteration 边界、reasoning/output delta、完整 Tool Call、错误、关闭与可选 usage counter。

owned string 在调用 `claw_agent_event_free` 前有效。每个成功接收的事件都必须且只能释放一次，包括被忽略的 delta 或 boundary event。

<Aside type="note">
  `cap_agent` 不会将每个 token 放入 Event Router。它将 `OUTPUT_DELTA` 聚合到 `OUTPUT_END`、保持 reasoning 在内部，并以 `source_cap=agent,event_type=out_message` 发布完整输出。
</Aside>

## C RPC 集成

C 系统始终调用同一个 Capability surface：

```json
{"method":"session.input","args":{"text":"hello"}}
```

Event Router 使用 `cap="agent"` 的 `call_cap` 执行它。Session/request ID 通过 `claw_cap_call_context_t` 传递；route/correlation 字段将异步输出绑定到原始 IM 会话。

`session.input` 在 `request_id` 非零时选择 `respond`，否则选择 `submit`。生命周期与显式控制方法使用相同的 `method + args` envelope。

规则链路详见 [Event Router](./claw-event-router) 与 [数据流与自动化](@lang/reference-project/dataflow-and-automation)。

## Tool 边界

AgentSystem 初始化时会将启用且对 LLM 可见的 C capabilities 快照为 Rust tools。工具执行通过 `claw_cap` 回到 C；`claw-agent` 自身不解析 C capability implementation。

`agent` capability 仅供系统调用，不标记为 LLM callable，从而防止递归自调用。

## 编译期 features

`claw-agent` 是 runtime shape 的 feature 边界：

- `reasoning_short`、`reasoning_medium`、`reasoning_long` 必须三选一，用于设置累计 reasoning 字节上限。
- `stage_verbose` 将详细 stage 支持传递给 `claw-core`。
- `multiagent` 编译 Session-scoped subagent graph 与 lifecycle tools。
- `cache_profile` 启用 provider token/cache usage diagnostics。
- `host-backends` 与 `dev` 是 host workflow bundles，不是固件必需项。

`claw-cabi` 拥有 C boundary features：

- `prod_logging` 保留轻量 `log` callsites，并在编译期移除 structured tracing。
- `rich_logging` 安装 structured tracing，并在编译期移除重复 plain-log callsites。
- `cache_profile` 通过启用 `USAGE` 改变 C event ABI。

固件 CMake build 当前选择 `prod_logging` 与 `claw-agent/reasoning_medium`。

## 错误模型

ABI 返回 `esp_err_t`：

- `ESP_ERR_INVALID_ARG`：ID、UTF-8、配置或参数无效。
- `ESP_ERR_INVALID_STATE`：生命周期状态无效或 input request 已过期。
- `ESP_ERR_NOT_FOUND`：Session 未知或尚未打开。
- `ESP_ERR_TIMEOUT`：bounded receive 在时限内没有事件。

interrupt 与 cancel 是协作式的；应继续消费 Session stream，直到观察到终止 turn 或 closed event。
