## Role

`cap_llm_inspect` analyzes a local image through a **standalone inference client owned by the capability**. It does not depend on `claw_core` or enter the Agent request loop.

Its scope is deliberately narrow:
- Read one supported local image
- Send one image-and-prompt request
- Return the provider's text response

## Tool surface

`cap_llm_inspect` registers a single Callable, `inspect_image`:

| Tool ID | `inspect_image` |
| :-------:|----------------|
| Description | Analyze a local image from an absolute path. <br /> Confirm the path first, then provide a prompt describing what to inspect. |
| Input | `{ "path": "<absolute path>", "prompt": "<what to inspect>" }` |
| Output | Textual analysis from the LLM |

**Typical flow:**

```d2
user: "User"
cap_im: "cap_im_platform"
fatfs: "FATFS"
router: "Event Router"
inspect: "inspect_image\n(cap_llm_inspect)"
llm: "LLM\nmultimodal infer"
send: "(im)_send_message"

user -> cap_im: "send image"
cap_im -> fatfs: "download save"
cap_im -> router: "attachment_saved event"
router -> inspect: "call_cap\n(rule fired)"
inspect -> llm: "image + prompt"
llm -> inspect: "analysis"
inspect -> send: "result text"
send -> user: "reply"
```

## Core idea: standalone image inference

The capability owns only image preparation, the provider request, and the HTTP response. Core flow:

```c
static const char *CAP_LLM_INSPECT_SYSTEM_PROMPT =
    "You analyze local image files for the ESP32 claw. "
    "Describe visible content plainly and briefly. "
    "If the image is unclear, say what is uncertain instead of guessing.";

static esp_err_t cap_llm_inspect_execute(const char *input_json,
                                          const claw_cap_call_context_t *ctx,
                                          char *output, size_t output_size)
{
    // Parse and validate path and prompt before this excerpt.
    char *analysis = NULL;
    char *error_message = NULL;

    xSemaphoreTake(s_runtime_lock, portMAX_DELAY);
    if (!s_runtime) {
        err = ESP_ERR_INVALID_STATE;
        error_message = strdup("LLM image inference is not configured");
    } else {
        err = cap_llm_inspect_runtime_infer_image(
            s_runtime,
            path_json->valuestring,
            CAP_LLM_INSPECT_SYSTEM_PROMPT,
            prompt_json->valuestring,
            &analysis,
            &error_message);
    }
    xSemaphoreGive(s_runtime_lock);
    snprintf(output, output_size, "%s", analysis);
    free(analysis);
}
```

### Unlike the main Agent chat

The private `cap_llm_inspect` runtime is isolated from the user-facing Agent session:

- Uses its own `system_prompt` (image-focused, no chat history)
- Does not consume or persist the current session context
- Does not go through `cap_skill` tool-visibility management
- Requires multimodal support from the configured backend

### Error handling

```c
if (err != ESP_OK) {
    snprintf(output, output_size,
             "Error: image analysis failed (%s)%s%s",
             esp_err_to_name(err),
             error_message ? ": " : "",
             error_message ? error_message : "");
    free(error_message);
    return err;
}
```

If multimodal is unavailable or the path is bad, the error string is returned in `output` to the caller (LLM or automation).

## Design takeaways

`cap_llm_inspect` highlights several choices:

1. **Dedicated system prompt**: image work should not be biased by conversational history; a fixed specialist prompt stabilizes tone.

2. **“Confirm the path first”** in the description: the LLM should use `cap_files` `list_dir` before sending a request for a wrong path.

3. **No session state**: only copied provider configuration is retained; every image request is independent.

4. **Separation of concerns**: IM downloads live in `cap_im_platform`, paths in `cap_files`, analysis here.

## Deliberate scope

The capability intentionally does not include:

- Audio or document processing
- Agent history, tool loops, or context persistence
- Streaming, retry, or a generic provider framework

<Aside type="tip">
  **Why keep it narrow?**
  `inspect_image` needs one local image and one semantic result. Extra Agent-runtime features would increase coupling without helping that job.
</Aside>
