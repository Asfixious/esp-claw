## Responsibilities

`claw-agent` is the public Rust assembly boundary for AgentSystem. It owns Sessions, model bindings, tools, persistence, and the lifecycle driver. `claw-cabi` exposes that runtime to ESP-IDF through `claw_agent.h`.

The C application does not duplicate the Agent loop. It uses `cap_agent` as a system-only RPC adapter and receives asynchronous results as Event Router events.

```d2
app: "app_claw\nlifecycle + API config"
rpc: "cap_agent\nmethod + args"
runtime: "claw-agent\nAgentSystem + Sessions"
router: "Event Router\nout_message"

app -> runtime: "claw_agent_init/start/link_api"
rpc -> runtime: "claw_agent_session_*"
runtime -> rpc: "Session event stream"
rpc -> router: "claw_event_router_publish"
```

## Lifecycle

| API | Effect |
| --- | --- |
| `claw_agent_init` | Construct one stopped AgentSystem, restore persistence, and optionally link the initial root API |
| `claw_agent_link_api` | Link or replace an API for root Agent, subagent, memory, or compaction |
| `claw_agent_start` | Activate tools and enable Session operations without reconstructing AgentSystem |
| `claw_agent_stop` | Deactivate tools while retaining bindings, Sessions, open streams, and runtime state |
| `claw_agent_deinit` | Stop if needed and destroy the retained AgentSystem |

All four initial API fields may be empty. This creates an unbound runtime that can be configured later with `claw_agent_link_api`. A partially configured initial API is rejected.

API replacement becomes visible at the next turn boundary and does not disturb an in-flight turn.

## Sessions

Sessions use non-zero numeric `uint32_t` IDs. Creation explicitly chooses `PERSISTENT` or `EPHEMERAL`.

The main operations are:

- `claw_agent_session_create` / `list`
- `claw_agent_session_open`
- `claw_agent_session_submit`
- `claw_agent_session_respond`
- `claw_agent_session_interrupt` / `cancel`
- `claw_agent_session_receive`
- `claw_agent_session_close` / `delete`

`submit` appends input to the Session FIFO, including while another turn is active. `respond` is different: it resumes the current turn and requires the `request_id` from `INPUT_REQUESTED`.

Opening a Session creates one event stream. In the production IM/RPC path, `cap_agent` is the only stream consumer and runs one event pump per opened Session. The diagnostic CLI owns only the ephemeral streams it creates itself.

## Events and ownership

`claw_agent_session_receive` yields a tagged `claw_agent_event_t`. Read only the union member selected by `kind`.

The stream includes turn boundaries, input requests, iteration boundaries, reasoning and output deltas, complete tool calls, errors, closure, and optional usage counters.

Owned strings remain valid until `claw_agent_event_free`. Every successfully received event must be freed exactly once, including ignored delta or boundary events.

<Aside type="note">
  `cap_agent` does not enqueue every token into Event Router. It coalesces `OUTPUT_DELTA` until `OUTPUT_END`, keeps reasoning internal, and publishes complete output as `source_cap=agent,event_type=out_message`.
</Aside>

## C RPC integration

The C system always calls the same capability surface:

```json
{"method":"session.input","args":{"text":"hello"}}
```

Event Router executes this through `call_cap` with `cap="agent"`. Session and request IDs are passed through `claw_cap_call_context_t`; route and correlation fields bind asynchronous output to the originating IM conversation.

`session.input` selects `respond` when `request_id` is non-zero and `submit` otherwise. Lifecycle and explicit control methods use the same `method + args` envelope.

See the [Event Router](./claw-event-router) and [Dataflow and automation](@lang/reference-project/dataflow-and-automation) pages for the rule path.

## Tool boundary

AgentSystem snapshots the enabled LLM-visible C capabilities as Rust tools during initialization. Tool execution crosses back through `claw_cap`; `claw-agent` does not resolve C capability implementations itself.

The `agent` capability is system-only and is not marked callable by the LLM, preventing recursive self-invocation.

## Compile-time features

`claw-agent` is the runtime-shape feature boundary:

- Exactly one of `reasoning_short`, `reasoning_medium`, or `reasoning_long` selects the accumulated reasoning-byte cap.
- `stage_verbose` forwards detailed stage support to `claw-core`.
- `multiagent` compiles the Session-scoped subagent graph and lifecycle tools.
- `cache_profile` enables provider token/cache usage diagnostics.
- `host-backends` and `dev` are host workflow bundles and are not firmware requirements.

`claw-cabi` owns the C-boundary features:

- `prod_logging` keeps lightweight `log` callsites and compiles structured tracing out.
- `rich_logging` installs structured tracing and compiles duplicate plain-log callsites out.
- `cache_profile` changes the C event ABI by enabling `USAGE`.

The firmware CMake build currently selects `prod_logging` and `claw-agent/reasoning_medium`.

## Error model

The ABI returns `esp_err_t`:

- `ESP_ERR_INVALID_ARG` for invalid IDs, UTF-8, configuration, or arguments.
- `ESP_ERR_INVALID_STATE` for invalid lifecycle state or stale input requests.
- `ESP_ERR_NOT_FOUND` for unknown or unopened Sessions.
- `ESP_ERR_TIMEOUT` when a bounded receive has no event.

Interruption and cancellation are cooperative. Continue draining the Session stream until its terminal turn or closed events are observed.
